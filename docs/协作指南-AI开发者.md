# 协作指南：AI 开发者

> 读者：AI 协作者（Agent）。人类侧见 [`协作指南-与AI协作的人类.md`](协作指南-与AI协作的人类.md)、
> [`协作指南-独立人类开发者.md`](协作指南-独立人类开发者.md)。
> 阶段流程见 [`无障碍补丁流水线.md`](无障碍补丁流水线.md)（分工表 §7、出口清单 §8）。
> 本文是你的**操作纪律**：任何结论带证据，任何改动先能证伪，任何验证状态如实标注。

## 1. 定位

你是执行者，不是裁判。你的产出要经得起人类按 `file:line` 抽查。

## 2. 五条上下文纪律

1. **结论进对话，产物落盘**：反编译摘要、探针转储、统计输出一律写入 `evidence/` 或 `docs/` 下的文件；
   对话里只留结论 + `file:line` 引用 + 验证标签。大块转储禁入对话。
2. **只读分析与修改分离**：审计用只读子代理（每个只审一块），结论必须带 `file:line` +
   `[已实机验证]`/`[未验证]`；主代理只负责改，**不给自己发验证通过**。
3. **可复现优先于复述**：一个结论的复现成本必须低于重读源码，否则不值得写；
   工具链锁定（`tools/versions.lock`：工具 + 版本 + 来源 + 哈希，如 ilspycmd / UnityPy / unrpyc），
   换版本 = 旧证据作废重跑。
4. **知识按阶段加载**：按 P0–P8 需要加载对应章节（见 §6 地图），维护分阶段清单；
   禁止整读流水线全文（108KB 级文档按需取段）。
5. **会话卫生**：单任务单会话；阶段边界压缩上下文；复盘结论**立即落盘**（写进文档才算沉淀）。

## 3. RE 结论的强制格式

```
断言：（一句话结论，写成能被证伪的句子）
证据：（反编译 file:line / probe_full_dump.log 行号 / scene_tree.txt 条目 / 哈希对照）
验证：[已实机验证] 或 [未验证]
```

- **探针优先于反编译推测**：能实机探针确认的，不许用反编译推断代替。
- AI 产出的反编译摘要必须经「原文片段二次比对」或「实机探针确认」后才可进代码。
- 跨引擎经验**分轨**：通用纪律（契约 / 证据 / 发布）四路通用；一次性技巧（xp3 注入、TJS2 ABI、
  NVDA 双进程等）只在对应路线 playbook 里加载，不许拿 KiriKiri Z 的招数改 Unity 的代码。

## 4. 三条铁律（违反任何一条 = 返工）

1. **不许猜方法名和对象名**——只接受三个来源：反编译实查、探针转储、既有 G 清单记录。
2. **不许把没实测说成已验证**——允许写「尚未实机复测」，不允许无依据的「已验证」。
3. **别名表 / 排除名单每条注释写明依据**（探针条目或反编译出处）。

## 5. IP 与合规红线

- 证据、日志、文档不得含游戏文本 / 截图 / 剧透；`[朗读]` 日志 = 剧本原文，不得入库。
- 反编译 / 解包产物不得入库；只入结论与自研代码。
- 发布包不打包 `interop\`、`unity-libs\`、`config\<guid>.cfg`、`dl\` 缓存（流水线 P6 十二项自检）。

## 7. 产出物落盘规范

| 产出 | 落到哪 | 对话里留什么 |
|---|---|---|
| 反编译摘要 | `evidence/`（或 `re/` 笔记） | 结论 + `file:line` + 标签 |
| 探针转储 / 场景树 | `evidence/`（probe_full_dump.log、scene_tree.txt） | 用到的条目引用 |
| 统计与 diff | 脚本 + 输出文件 | 数字结论 |
| 文档改动 | `docs/` 对应文件 | 变更点列表 |

## 8. 收工标准

四件套回灌不齐不算收工（每作收尾强制）：全仓库矩阵、实践经验章节、G 陷阱增量、模板差异；
新知识入库带验证强度标注（`[已实机验证]` / `[未验证]` / 「尚未实机复测」）。
