# 协作指南：独立人类开发者

> 读者：不用 AI、一人走完 P0–P8 的开发者。
> 与 AI 协作见 [`协作指南-与AI协作的人类.md`](协作指南-与AI协作的人类.md)，
> AI 协作者见 [`协作指南-AI开发者.md`](协作指南-AI开发者.md)。
> 阶段流程主线见 [`无障碍补丁流水线.md`](无障碍补丁流水线.md)。

## 1. 定位

流程不变，只是每一步亲手做。本文给两样东西：**手工执行的最短路径**，和**一个人最容易漏的检查**。

## 2. 阶段手工要点

| 阶段 | 手工做什么 | 出口 |
|---|---|---|
| P0 | 照 [`templates/无障碍可行性验证.md`](templates/无障碍可行性验证.md) 写满量化问题（剧本行数 / 配音覆盖 / 说话人分布 / 选项数 / 富文本 / UI 技术栈 / 引擎宿主） | 「能不能做 + 最贵的三处」 |
| P1 | 照 `probe/` 跑探针，证据落 `evidence/`；结论写断言句带出处；转储只含类型名 / 方法名 / 对象名 / 控件标签 | 补丁点存在性逐个确认 |
| P2 | `tools/new_game.py --route mono\|il2cpp` 生成骨架；先结构冒烟再 `dotnet build` | 骨架编译通过 |
| P3 | 按依赖序实现（不许跳）：TextProc 离线先行 → 台词朗读最短闭环 → 选项+重读 → 限时 → 界面导航 → 本作特有形态 → 现实时间等待 → 感知缺口 | 每个补丁点先在探针转储里确认过 |
| P4 | 三层测试缺一不可：插件内 SelfTest / 进程外 Harness / 人工听觉；[`templates/测试问卷.md`](templates/测试问卷.md) 十节走全 | 第 8 节（回归）是硬要求 |
| P5 | `build.ps1` 五步；构建前确认游戏没在跑（dll 被占用会静默覆盖失败）；版本号纯数字四段 | `[BepInPlugin]` = csproj = CHANGELOG 三处一致 |
| P6 | `release.ps1` + `tools/makezip.ps1`；12 项自检任何失败即停 | 发布包可从干净克隆重建 |
| P7/P8 | 文档与提交前守卫 | 流水线 §8 出口清单逐项过 |

## 3. 一个人最容易漏的

1. **「日志全绿、功能全死」**：没有 SelfTest + Harness + 耳朵三层，分不清「加载了」和「工作着」。
2. **版本号字母后缀**（G32）：`0.5.8a` 会被 BepInEx 判 `version is invalid` 并静默跳过整个插件；想写 0.5.8a 就写 0.5.8.1。
3. **合成输入 ≠ 真实输入**（G22/G24）：自动化点击 / 按键只当辅助证据，不当验收证据。
4. **手工打包**：`Compress-Archive` 的反斜杠条目会让 Linux unzip 失败；历史事故是「包内容自检从没通过过却照发」。
5. **记忆不可靠**（G33）：改前改后按 tag 逐文件哈希对照，别凭印象——一个人没有同事可以对账，更要用哈希。

## 4. 纪律（对人同样成立）

- 改动必须**先能证伪**：`py_compile` / `compile_check` / 骨架冒烟先行，失败先找原因。
- 别名表 / 排除名单每条注释写明依据（探针条目或反编译出处）。
- 证据与结论一起入库（机器 / 时间 / 版本），IP 红线不碰：剧本文本、截图、日志原文不入库。
- CHANGELOG 每个修改单独一节：现象 → 后果为何严重 → 怎么修；复测要点标「尚未实机复测」。

## 5. 工具箱速查

| 工具 | 用途 |
|---|---|
| `tools/new_game.py` | 生成新作骨架（Unity 路线；非 Unity 显式拒绝） |
| `tools/compile_check.ps1` | 平台层不引游戏类型守卫 + NameAlias 大小写守卫 |
| `tools/check-staged.ps1` | 提交前守卫 |
| `tools/makezip.ps1` | 发布 zip（条目分隔符全 `/`） |
| `tools/lint_repeat.ps1` | 重读缓冲区静态断言 |
| `probe/` | 最小探针插件与证据脚本 |
