> **这份文档回答一个问题：三源仓库与第 4–7 作都是 Unity，换成非 Unity 宿主之后，
> 哪些前提失效、哪些经验仍然成立。**

> - 规则归流水线：抽象后的铁律以

## 1. `SenrenBanka-For-Accessibility`：当引擎根本不加载插件

### 1.1 判定与不可复用边界

- 判定：`SenrenBanka.exe` 的版本资源 `ProductName=TVP(KIRIKIRI) Z core`、
  `FileVersion=1.2.0.3`，PE32，目录里没有 `Managed`/`il2cpp_data`。
- 不可复用：C++、32 位、DirectInput，**C# 平台层一行都用不上**。
- 可复用：`A11yHost` 的**语义**（后端链、唯一朗读出口、导航开关、诊断开关）、
  §4 的可达性纪律、§8 的出口清单、`zdsr_selftest` 式桩测试思路。
- 引擎功能全部经 `iTVPFunctionExporter` 的虚表下标 1
  `QueryFunctionsByNarrowString` 按**完整签名**取，再用 `TVPDoTryBlock` 包住每一次脚本调用
  （`<SenrenBanka-For-Accessibility>/src/a11y6.cpp`）。插件导出
  `V2Link`/`V2Unlink`/`GetModuleThreadModel`。

### 1.2 部署：没有「放进去就生效」这回事

引擎**不会**扫 `plugin\*.dll`。作者试过 13 种非破坏性外挂方式，全部失败；
唯一可行的预加载点是**游戏自己的启动脚本槽位** → 必须改 `data.xp3`。
反向证据：官方补丁 `patch.xp3` 里的脚本确实会执行，说明「改归档」不是胡说。

改归档的验收纪律（这是本条路线最贵的部分）：

1. **不能按哈希重建内层索引**：按 `adlr` 哈希重建会静默丢掉 18 个 storage，
   症状不是启动失败，而是剧本查找时的类型错误。
2. 验收 = **条目集合与顺序完全一致**（本作 1277 条）+ Python/C# 两套注入器产物
   **逐字节相同**（`51EB4E72…`，1,033,432,485 B）+ 体积差只来自 zlib 压缩。
3. 发布**不带**改过的 `data.xp3`（99.95% 是游戏资源），只发注入器 + 插件；
   玩家机器上注入约 4.5 秒。
4. 还原：只支持「加量模式」回滚；被改过的归档只能靠玩家自己的原始备份恢复
   （`<SenrenBanka-For-Accessibility>/docs/RESTORE.md`）。

### 1.3 导航：没有控件模型，只有坐标

- 1920×1080、40px 格点 + `kag.getPrimaryLayerAt(x,y)`，按层名去重。
- 子控件坐标**相对父层**；越出父层可见区域的子项 `visible=1` 但点不到，
  必须按 `cl<-1 || ct<-1 || cl+cw>parentW+1 || ct+chh>parentH+1` 过滤「假控件」。
- **不要按宽度丢容器**：1928 宽的设置容器里装着全部选项。
- 重扫只在「进入导航 / 激活之后 / 语言变化」发生（800ms 节流），并补
  +150/+400/+700ms 的延迟重扫；每个属性访问单独 `try/catch`
  （半空包装对象会抛 `Accessing to null object`，一次就把整轮扫描静默打断）。

### 1.4 输入：游戏读 DirectInput，PostMessage 没用

- `PostMessage` 的按键对 DirectInput 状态轮询不可见；子类化能**读**但不能**挡**。
- 游戏自己占用 Tab/方向键/Home/End/PgUp/PgDn/Esc/Backspace；补丁保留原生键，
  只补游戏不用的组合。
- 无焦点热键 = 200ms 定时器 + `GetAsyncKeyState` + 四道闸
  （找到游戏窗口 / 前台属于本进程 / 不在跳过模式 / 修饰键完全匹配）+ 按下沿闩锁。
- 非导航的 Enter/Space 走**真实鼠标点击**（`ClickLogical(ADVANCE_X, ADVANCE_Y)`）。
- 自动连点前先「试推」：前 3 下间隔 600ms（大于双击间隔），文本没变就中止
  （`SKIP_PROBE_MS=600`/`TRIES=3`/`STUCK_LIMIT=6`/`MAX_CLICKS=4000`）。

### 1.5 后端与构建硬点

- 后端链 Tolk → NVDA Controller → 争渡 → SAPI；初始化重试 10s，NVDA 可能晚启动，
  额外 5s 重试；F9 轮换；**失败只降级、绝不抛异常**。
- 调用约定：Tolk `__cdecl`，NVDA `__stdcall`，写错就是栈崩。
- SAPI 必须 `SPF_ASYNC`（同步会卡游戏线程）。
- 争渡五个细节：候选上限 16（尾部 4 个预留）、逐候选 `InitTTS=1` 兜底、
  不缓存「没找到」、同时探 HKLM/HKCU 两个 WOW64 视图、
  `LoadLibraryExW` + `LOAD_WITH_ALTERED_SEARCH_PATH` 用绝对路径。
- MSVC 的 `%ls` 在 C locale 下遇中文会**整行变空** → 统一
  `WideCharToMultiByte(CP_UTF8)`；日志每行 `WriteFile` + `CloseHandle`，别指望缓冲。
- 构建：`VCVARS32` x86；`VSCMD_ARG_TGT_ARCH=x86` 必须硬失败；
  `/MACHINE:X86` + 产物 PE `Machine=0x014C` 断言。x64 vcvars 会「成功」编出 x64 DLL，
  32 位游戏静默不加载。

### 1.6 发布纪律：两处「文档说关了，其实没关」

1. 调试 REPL 随发行 DLL 出厂：每 200ms 轮询 `D:\a11yb\sba11y_cmd.txt` 并执行任意 TJS；
   没有 `#ifdef`，文档却写「发布版已关闭」。→ G40：发布件必须 `grep` 调试通道。
2. 安装器无法从仓库重建（`.gitignore` 的 `*.tjs` 把 `data/startup.tjs` 也吞了）。
   → G45：安装器与辅助二进制必须能从仓库重建，否则下一个维护者只能拿到二进制黑盒。

> 本作版本 0.1.0.6 明确标 pre-release：「代码与自检都过了，但尚未在游戏里实机验证」。
> 这种标注方式就是 §6 P7 要求的诚实纪律。

## 2. `OurBriefEternityForAccessibility`：脚本运行时就是 API，但时序是契约

### 2.1 路线与分层

Ren'Py 没有编译、没有 Harmony、没有注入器；补丁是**往 `game/` 放若干 `.rpy`**，
靠引擎的「磁盘优先于归档」加载（`renpy/loader.py:108-109`），**不碰 `.rpa`**。
这让安装/卸载完全可逆，但也意味着：**钩子注册的时序错一拍，就静默失效**。

| 层 | 文件 | 行数 | 职责 |
|---|---|---|---|
| L1 | `00_contract.rpy` | 386 | 契约（单一默认 store + 具名槽位） |
| L1 | `01_speech.rpy` | 1610 | 后端链 |
| L1 | `05_repeat.rpy` | 218 | 重读缓冲区（**唯一朗读出口**） |
| L1 | `06_keymap.rpy` | 460 | 键位层 |
| L1 | `08_uialt.rpy` | 1083 | 焦点表 → 导航 → 滑杆 |
| **L2.5** | `10_renpy_adapter.rpy` | 1042 | **引擎适配层**：接管 `config.tts_function`，把引擎的整屏 `tts.displayable` 转成补丁的文本/控件描述 |
| L3 | `20_textproc` / `22_uialt` / `30_choice` / `31_main_menu` / `90_plugin` | 161 / 592 / 316 / 189 / 143 | 逐作清洗、文案表、选项、主菜单、启动 |

> L2.5 是这次新出现的层：**引擎适配不属于 L1**，否则 L1 会引用引擎私有对象，
> 下一个 Ren'Py 作品就没法整份复用。这条经验已写进流水线 §3.4。

### 2.2 init 顺序就是契约

```
init -200  00_contract.rpy        契约
init -190  90_plugin.rpy          逐作入口填 GameName / 版本 / 全部开关
init -103  05_repeat.rpy          重读缓冲区
init -100  01_speech.rpy          后端链
init  -60  20_textproc / 30_choice
init  -55  22_uialt.rpy           逐作文案表
init  -50  10_renpy_adapter.rpy   L2.5 接管 tts_function
init  -45  08_uialt.rpy           焦点表 / 导航
init 1200  06_keymap.rpy          **必须晚于引擎 00keymap.rpy 的 init 1100**
init 1300  90_plugin.rpy          validate → 启动 → 安装键位
```

顺序错 = 静默失效，**引擎 lint 仍然 exit 0**（G49）；所以需要 §2.8 的启动正向证据。

### 2.3 取文四挂载点

1. **对话**：`config.say_menu_text_filter`（`ast.py:971`）。
   `config.all_character_callbacks` 注册成功但真实 say 从不触发——**存在 ≠ 被调用**（G46）。
2. **说话人**：filter 比 `store._last_say_who` 赋值（`ast.py:985`）早，直接读会拿到
   **上一行**的说话人；必须先记文本 + 标志，下一帧再补说话人（G47）。
3. **选项/主菜单**：覆盖 `screen choice` / `screen main_menu` 加 `alt` 文本；
   声明式覆盖受加载顺序与 `init offset` 控制，注册错层就整段不生效（G48）。
4. **界面**：引擎焦点表 `renpy.display.focus.focus_list`（`focus.py:88-109`，每轮渲染重建）
   → 拉模型查表；不往控件里写东西（推模型 `style.alt` 注入实测不生效）。

`predict` 也会调用 filter，所以「记录」与「朗读」必须分离，否则预读的下一句会提前念出。

### 2.4 朗读三规则（按角色名判，不按配音文件判）

1. 无角色名 → 全文（旁白/独白）。
2. 有角色名 + 有配音 → **只报名字**，但整句必须 `remember` 进缓冲区并打断上一句。
3. 有角色名 + 无配音 → 全文。

本作旁白 2451 行 / 43.2%；若按「有没有配音文件」判，整段叙事会被漏掉。
三个会让判断失真的引擎行为：`voice_sustain=True`、配音音量 0、
`config.tts_voice_channels` 守卫（`tts.py:419-421`，任一 voice 通道在播就直接 return，
根本走不到 `tts_function`）——必须按行自己判。

### 2.5 队列与后端

- 唯一出口 `A11yRepeat.say()`；逐作不得绕过（`lint_patch.py` 断言 C 机械拦）。
- 自动播报排队**不打断**（`CfgInterrupt=False`）；玩家主动 F5 才打断；
  距上次 <1.5s 才不打断；去重 1.0s；`remember()` 只记不念。
- 送读前先落盘日志：曾硬崩 `0xC0000005` 且无 traceback，最后一行日志是唯一线索。
- 后端链 Tolk（自备）→ NVDA → 争渡 → 引擎同款 SAPI（**子进程** `wscript say.vbs`；
  裸 COM 直调会 `0xC0000005`）。争渡只认 `GetSpeakState()∈{3,4}`。
- F9 档位顺序「自动/Tolk/NVDA/争渡/SAPI」，不可用就跳过并**念出跳过了谁**；
  选择同时写 `persistent`（`init -190` 的配置每次启动会被重写）；失败**绝不** invalidate 后端。

### 2.6 导航：拉模型 + 三级查表

- 身份：焦点对象每轮重建，`id(w)` 不能当身份；用「控件路径/位置键」。
- 文案三级查表：idle 图片路径 → 屏幕坐标 → 序号（ordinal）。
  存档格差 46px 时按坐标会 12 格全哑，改用「同图 + (y,x) 名次」。
- 「查不到」与「值为 None」要返回**不同哨兵**，否则整片界面静默。
- 四级兜底永不静默；`TTSRoot` 的「别念我」与「未知控件」必须分开（G54）。
- 状态词 `selected` 被追加在 `_tts_all` 上（`behavior.py:1199-1205`），
  只筛一层 = 假修复，要连派生串一起筛。
- `Bar` 不是 `Button`：`_tts_all` 尾巴硬编码「栏」（`behavior.py:2664-2671`），
  名字第一来源 `value.alt`，取值接口有三种；只给 `get_selected()` 加「：当前」。
- 去重键 =（文案, 界面）+0.9s；值变化重念用位置键。
- 线性导航照抄 `focus_ordered` 但保留 viewport 焦点，按 (y,x)，到头不绕，
  最终调 `change_focus` 且移动后不朗读。
- **明确不需要导航模式**：引擎有原生焦点系统，加模式只会把原生行为挡在外面
  （作者删过一版 `07_uinav.rpy`）。这条与 UI Toolkit 作代价差一整个模式。

### 2.7 keymap 三条 Ren'Py 专属纪律

1. 登记必须 `init 1200`：`config.underlay` 在引擎 `00keymap.rpy` 的 `init 1100` 被整体赋值。
2. `renpy.Keymap` 的值是**无参调用**（`behavior.py:550-565`）；带参回调 `ev` 恒 `None`
   → F5 多版本不响（G50）。
3. 键名必须用引擎 `compile_event` 试解析（临时 `config.developer=True`）；
   写错键名（如 `K_KP_UP`）会让游戏**起不来**。常数从引擎读：
   Ren'Py 8 没有 `pygame` 模块，`KEYDOWN=768` 不是 2。
   不抢 Backspace（`input_backspace`）；F5 先提示音再朗读（三分判别）。

### 2.8 验证体系：把「没报错」变成「跑起来了」

- `tools/lint_patch.py` **12 条静态断言**：A0 `.rpy` 无 BOM / A `ast.parse` /
  A2 顶层语句 / B L1 无逐作标识符 / C 不绕过 Repeat / D `K_` 常量 /
  E Keymap 无参 / F 钩子注册行 / G 版本 = git tag / H `install.ps1` 清单覆盖所有 `.rpy` /
  I 契约属性有定义 / J `.ps1` 必须有 BOM。
  > 注意 BOM 规矩相反：`.rpy` 不能有，`.ps1` 必须有（G5）。
- `tools/check_boot.py` **八条正向证据**：契约打印 / 接管 `tts_function` / 后端结论 /
  适配层启动 / 重读键 / 按键层 / 导航键 / 无配音角色推导。
- 探针覆盖：后端、键位、ordinal、状态词、焦点键、播报窗口、`Bar` 路线、game 名字。
- 文档：`无障碍可行性验证.md` 670 行（多「依据」列；§4.1 三处麻烦直接编码到引擎源码行；
  §4.4 不要导航模式；§7 返工复盘；§8 界面适配）；`测试问卷.md` 271 行/15 节
  （按键整表 + 三分判别 + 未知控件收集 + 双日志）。

### 2.9 发布与许可

- 安装 = 复制 `game/` 下的松散 `.rpy` 叠加层；`install.ps1` 只用于开发期。
- 发布 zip：白名单不含 `.ps1`；条目只落 `game/`、包根、`licenses/`；条目分隔符 `/`；
  固定时间戳可复现；**打包前 IP 自检，命中即报错退出**。
- 版本号从代码解析，并与 git tag、包名三方校验。
- 许可：根 MIT；NVDA Controller Client（LGPL-2.1）随包；争渡 DLL 只进包不入库，
  且不带 `ZDSRAPI.ini`。
- `docs/已验证版本.md` 逐版本写「谁验过 / 什么状态 / 哪版不要用」。

### 2.10 未验证

争渡真出声、NVDA「只响第一条」根因、F10 整屏朗读（实测无效，已从玩家文档撤下）、
界面文案在每种组合下的实听、0.0.1.7 未打 tag 未耳测（推荐稳用 0.0.1.5）。

## 3. `SisterOtherParanoiaForNVDA`：不采纳的路线 + 五条方法学

### 3.1 为什么否决

它是「游戏内 BepInEx 插件 + NVDA 全局插件」的**双进程**方案：C# 侧挂钩 Naninovel，
通过本机 TCP 把事件发给 NVDA Python 插件。结论：**不进主线**。

- 这不是「第四种 L3 补法」，而是**换宿主**：屏幕阅读器从「补丁调用后端」变成
  「NVDA 侧独立应用」，玩家安装从 1 步变 2 步。
- L1 完全不可复用：Python 侧重新实现了 Repeat、优先级、历史、配置。
- 违反「逐作朗读只经 Repeat.Say/Note/Push」的纪律；配置两份，必然漂移。
- 只支持 NVDA 一个后端；协议无握手、无长度上限、无认证。
- 仓库无 LICENSE，版本四处不一致（manifest 1.3.0 / Plugin 1.2.0 / hello 1.1.0 / doc 1.0.0），
  脚本硬编码本机路径，BepInEx 下载无校验和。

### 3.2 可回收的五条方法学

1. **假对端探针**：`probe.py` 向端口注入六类事件，`event_listener.py` 截获游戏侧事件，
   **不装 NVDA 也能测协议** → 可推广为「只记录不朗读」的 Speech 后端 + 零 NVDA 断言。
2. **里程碑长跑**：`auto_advance.py` 每 5s 按 ENTER，记录 5 个里程碑，300s+ 无人值守。
3. **稳定性采样**：每 20s 记录 `Process.Responding`；「clickable scan took」>100ms
   落日志 → 性能从「一次测量」变成「分布」。
4. **点击命中闭环状态机**：`Idle → Pressed 0.12s → Restoring 0.2s → Verifying 0.25s →
   Retrying 0.4s`，用 onClick 标志/反射回读验证，主点 + 周围 2% 共 5 个尝试点
   （`ClickAssist.cs:999-1076`）。
5. **世界热点用虚拟鼠标/手柄**：`InputMode.Gamepad` + `VirtualMouseController.WarpCursor`
   + `Mouse.current` + 手柄 South；UI 先试反射 `VirtualMouseInput.m_VirtualMouse`，
   不行再 `SendInput`（`ClickAssist.cs:845-961`）。

## 5. 结论：框架边界重画

1. **L1 只服务 Unity（Mono / IL2CPP）。** KiriKiri Z、Ren'Py、NVDA 双进程的宿主层
   各自独立，不能塞进 `platform/`。
2. **契约与纪律跨引擎。** `A11yHost` 的语义、唯一朗读出口、可达性五条、
   证据/配置/发布纪律、§8 出口清单，对四种路线都成立——只是落地形态不同。
3. **生成器必须 route-aware。** `new_game.py --route unity|krkrz|renpy` 生成不同骨架，
   否则「生成一个能编译的空项目」这件事本身就不成立。
4. **文档按路线分叉。** 主线（Unity）保留 P0–P8；非 Unity 只走 §3.3–§3.5 的路线判定 +
   §5.5–§5.7 的专属纪律，不硬套 Unity 的平台层步骤。
5. **参考实现不能只看「有没有实机验证」这一行字。** 第 8 作只到自检、第 10 作没有证据，
   引用时必须在正文里带上强度，不能让后来的读者以为它们和 manosaba 同级。
