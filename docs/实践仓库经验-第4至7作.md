## 1. aliya_a11y：UI Toolkit 与「补丁没反应」的取证学

### 1.1 分水岭：这作一个 uGUI 控件都没有

本作界面全部是 **UI Toolkit**（`VisualElement` / `resolvedStyle` / `worldBound`），
没有 `Selectable`、没有 `EventSystem`。`platform/UiNav.cs` 的两条根基
（扫 `Selectable`、按 Canvas 分组）同时失效，导航不是「怎么点」的问题，而是
**「控件在哪里」的问题**——本作因此另写了 `VeNav.cs`（面板模式导航）和
`GameRefs.cs`（UI Toolkit 元素发现/可见性/激活/标签）。

**结论**：导航引擎必须能按 UI 框架分后端。Framework 现在只有 uGUI 一套，
下一个 UI Toolkit 项目仍会从零重写一遍（`aliya_a11y/mod/src/AliyaA11y/VeNav.cs:11-31`）。

### 1.2 UI Toolkit 导航的六条硬约束

1. **「隐藏」有两套写法**：内联 `style.display = None` 和样式表 `.hidden{display:none}`。
   只查 `style.display` 会读到 `Null`，把关着的面板当可见（v0.1.0.0 实测念出过
   本不该出现的面板文字）。必须查 `resolvedStyle.display`。
   （`aliya_a11y/mod/src/AliyaA11y/GameRefs.cs:192-203`）
2. **可见性要四道判据**：panel 非空 + 祖先链无隐藏（逐级 `parent` 查）+
   `resolvedStyle.visibility != Hidden` + `resolvedStyle.opacity > 0.01` +
   `worldBound` 宽高 ≥ 1。（`GameRefs.cs:204-239`）
3. **点击不能走 `Button.clicked` / `SimulateSingleClick` / `NavigationSubmitEvent`**：
   `Button.clicked` 只是转发到 `clickable.clicked`；`SimulateSingleClick` 是 `internal`；
   `NavigationSubmitEvent.target` 不可写。可行路径是反射 `Clickable` 的私有委托字段
   `clicked` 后 `Invoke()`——效果等同真人点一下，游戏自己的音效/置灰/高亮回调都会走。
   （`GameRefs.cs:128-167`；实机证据 `aliya_a11y/README.md:276-295`）
4. **「没接线」要与「点失败」区分**：读同一个私有字段即可判定 `HasClickHandler`，
   用于选项失败时回退到业务确认委托。（`GameRefs.cs:174-190`、`Patches.cs:50-56`）
5. **控件命中后不递归进子树**：UI Toolkit 里 `Label` 在子节点上是常态，
   递归必然重复播报。角色判定用 `ve is Button || Toggle || Slider || TextField`。
   （`VeNav.cs:219-238`）
6. **「控件 → 标签」在 UI Toolkit 里必须自己找**：设置面板的滑条没有 `label`，
   标签是排在控件前面的独立 `Label`（可能在别的容器）。三级回退：
   同父里控件之前的最后一段文本 → 往上 1–3 级祖先同样找 → 父节点子树第一段文本。
   文字取值顺序：`TextElement.text → Toggle.label → Slider.label → 子树首个非空文本`。
   （`GameRefs.cs:242-265`、`:319-411`）

### 1.3 面板模式：重扫、Esc、让键、图片遮罩

- **重扫不是每帧，而是「列表失效时才重建」**：列表为空 / 索引越界 / 当前项不可见
  才重建，另加 1.5 秒定期刷新；重扫不重复念。
  注意这与流水线 G11「重扫不能定时」**表面冲突**：G11 的教训是「0.35 秒重扫撞上
  场景销毁 → 原生崩溃」，判据应是**重扫是否触碰会被销毁的场景对象**。面板模式下
  UI Toolkit 元素随面板存活，1.5 秒重扫未复现崩溃（短时实机；长期未验证）。
  （`VeNav.cs:77-120`、`:181-217`）
- **Esc 必须能关面板**：原版只能点面板外空白关闭，键盘玩家没有出路；按面板名
  `Q(name)` 后把 `display` 设为 `None`，与游戏自己关面板一致。Esc/Tab 先关面板再退导航。
  （`VeNav.cs:123-142`、`:61-67`）
- **导航要主动让键**：Alt 按住时直接 `return`，把 `Alt+↑` 让给「聊天记录浏览」。
  （`VeNav.cs:77-120`）
- **图片放大遮罩要能被导航接管**：原版必须鼠标点一下才关；`PickRoot` 优先级
  `ImageMask → 面板名 → uiRoot`，左右键在遮罩打开时直接关掉它。
  （`VeNav.cs:163-179`、`:308-338`）
- **面板全量朗读要排除聊天区与选项区**（二者各有自己的快捷键），复用同一套
  `LinesOf(excludeChat:true)`。（`VeNav.cs:345-360`）

### 1.4 Harmony 与「游戏把插件的 Update 停掉」

这是本作最值钱的一节，症状全部是「日志全绿、功能全死」。

1. **补丁方法写成嵌套类 = 静默不打补丁**：`PatchAll` 不报错、日志只有「补丁已应用」，
   但游戏事件一个都抓不到；表现是「快捷键能用、状态能念，聊天消息一条不念」。
   修法：补丁方法必须直接声明在 `Patches` 类体内，并在 PatchAll 后把
   `Harmony.GetPatchedMethods()` 的条数与预检 N 一起打进日志。
   （`Patches.cs:8-33`；对照流水线 G2——G2 只覆盖「参数名写错 → PatchAll 抛异常」）
2. **「挂载点数量」要当断言写进日志**：预检 N + 已应用 N，期望值交给离线脚本核对；
   数量变少就是游戏更新。（`aliya_a11y/probe/analyze_log.ps1:3-20`）
3. **游戏会在某些剧情状态停止调用插件的 `MonoBehaviour.Update`**：现象是 Awake 跑到、
   Update 一次都没有，回装旧 DLL 同样失效（所以不是补丁改坏）。
   修法：**每帧驱动双通道**——① 自己的 `Update`；② 挂游戏自身每帧方法的 Postfix
   （本作用 `TimeMgr.Update`），用 `Time.frameCount` 去重。
   （`Frame.cs:10-27`、`Patches.cs:230-242`）
4. **心跳文件 + 异常文件是「补丁没反应」的第一取证手段**：每 2 秒无条件写心跳
   （驱动方式、帧数、前台窗口标题、最近按键、语音后端）；异常按「同一处只记第一次」
   写独立文件，每次启动清空。（`Frame.cs:130-195`、`Plugin.cs:123-145`）
5. **每帧逻辑逐模块 try/catch**：原先一个 try 包全部，某个状态抛一次就整局停摆
   （心跳还在、功能全死）。（`Frame.cs:49-98`）
6. **能读公开属性就不要挂补丁**：数值、开关、等待起止全部每帧读公开属性；
   等待起止靠状态迁移检测。（`Status.cs:8-30`、`:41-57`）
7. **异步开关（设备/滑条）Prefix 存 `__state` + Postfix 延后读终态**，且「状态没变」
   （被游戏拒绝）不许播报，否则用户以为操作成功。（`Patches.cs:85-163`）
8. **挂「实现」不挂「包装」**：通知是命令直接调 `INotifications` 实现，
   挂 `Utilities.ToastHelper` 包装类会漏。（`Patches.cs:174-196`）
9. **注释会漂移**：`Plugin.cs` 的补丁点一览仍写旧的 `ToastHelper`，代码已改挂实现——
   模板/工具应允许「注释与代码不一致」被 lint 抓出来。（`Plugin.cs:14-52` vs
   `Patches.cs:174-196`）

### 1.5 朗读层：Framework 缺「队列」这一层

Framework 的 `platform/Speech.cs:478` 是直接调后端，没有排队语义。本作的教训：

1. **排队朗读必须下沉成一层**：除「重读/出错」外谁都不打断谁；Message/Prompt 全部
   入队，每帧出队一条、以 `interrupt:false` 交给后端；队列上限 200（超了丢最旧），
   单条 >400 字按句末切段（软下限 60、硬切前回退 80 字找标点）。
   （`aliya_a11y/mod/src/AliyaA11y/Reader.cs:11-58`、`:241-246`）
2. **去重要按来源分开**：Prompt 类按「3 秒内完全相同文本」压掉；Message 类**绝不去重**
   （同文重复是剧情）。（`Reader.cs:335-336`）
3. **标点三档可配**（无标点 / 保留句末 / 全保留）：根因是读屏「标点级别＝全部」时
   把 `：；` 逐字念成符号名；本作**自己拼的公告串禁止出现 `：` 与 `；`**
   （「第 N 个」后面是空格）。（`TextProc.cs:45-70`、`Choices.cs:127-153`）
4. **读档静音不能以 `GameLoadOver` 为界**：新开局的片头也跑在它之前，会把开场白整段
   吞掉；正确界是「读档流程（`GameMgr.Load`）期间」，且读档会把当前消息以
   `isNewMsg:true` 重发一遍。（`Chat.cs:44-59`）
5. **选项要「攒一批」再播**：选项逐个加进窗口（约 0.45 秒窗口），一次念完并编号 1–9；
   确认后游戏代发的那条消息与选项正文重复，用「60 秒内刚播报过」抑制。
   （`Choices.cs:9-23`、`:93-101`）
6. **合成输入会重复报 `GetKeyDown`**：脚本/宏下一次 Tab 会得到「进入→退出→进入」
   三次迁移，必须「松开闩锁」——抬起才解锁，一次按下-抬起最多算一次。
   （`KeyEdge.cs:6-29`；Framework `platform/KeyEdge.cs:26-45` 已有同语义）
7. **组合键会「连带动」单键功能**：`Ctrl+Alt+F3` 里 F3 是 EOG 开关，单键路径必须加
   「纯按键」判定（无 Ctrl/Alt 才响应）。Framework `platform/Hotkey.cs:39-40` 已有
   这条约束，本作在逐作层又重写一份 `KeyEdge.ParseCombo`——建议收敛回平台层一份。
   （`Plugin.cs:561-623`、`KeyEdge.cs:90-127`）

### 1.6 现实时间等待与限时选项

流水线 §4 只有「倒计时只拉长不取消」一句原则，本作补上了**怎么找到并跳过等待**：

1. **等待不是「读文字按继续」**：剧情等待按现实时间走、截止时刻存存档、关机也走；
   原版 PC 没有跳过入口（倒计时是画出来的图，读屏拿不到）。
   （`aliya_a11y/mod/src/AliyaA11y/Skip.cs:7-41`）
2. **跳过分四路，唯一不跳的是限时选项**：
   ① 打字等待 → 取消发送延迟；② 剧情等待 → 游戏自己的 `SkipWait()`；
   ③ 剧本禁止跳过 → **只把截止时刻改成现在、不碰存档里的 `PlayerCanSkip` 字段**
   （下一帧游戏自己走正常结束流程，不跳过剧本命令、不写坏存档）；
   ④ 按住 0.4 秒连跳，只有第一下出声。
   **限时选项的截止时刻等于替玩家按默认分支，必须拒绝并提示按数字键。**
   （`Skip.cs:141-251`；实机两次跳过 `probe/evidence/v0010_跳过等待_验证.md:43-53`；
   「限时选项不跳保护」当时没赶上窗口，未验证 `v0010:101-110`）
3. **「正在等待」的判据不要靠猜**：打字等待用游戏自己的「输入中」动画控件可见性
   （每条消息前置开、`WaitSendMessage` 后置关），明确不能用会被重置的字段。
   （`Skip.cs:263-276`）
4. **限时选项延长用 `Prefix ref DateTime`**：只在「选项面板确有选项」时延长，
   已过期不动；同一重载还被「剧情现实等待」复用，不判上下文会把所有等待都拉长。
   **`ref` 参数不能进 lambda（CS1628）**，try/catch 必须手写。
   （`Patches.cs:286-315`；延长本身实机样本 0 条，未验证）
5. **等待播报门槛取游戏自己常量**（倒计时动画显示阈值＝30 秒），拿不到才退回 30 秒；
   否则会为 2 秒的等待念一句废话。（`Status.cs:168-174`）
6. **跳过与等待播报互相消音**：跳过念了「已跳过」，等待结束检测会紧接着再念
   「等待结束」，需要一次性消音开关。（`Status.cs:59-67`）

### 1.7 启动与发布：Steam 是旧文档的空白

1. **UnityDoorstop 会往自己进程环境写 `DOORSTOP_DISABLE` / `DOORSTOP_INITIALIZED`**
   （防重复注入），子进程继承；「直连启动 → 游戏调 `steam://run` 把自己交给 Steam」
   这条链会把变量传给 Steam，此后 Steam 启动的**所有**游戏一律注入不进去，
   且**连 `LogOutput.log` 都不生成**。（`aliya_a11y/CHANGELOG.md:76-128`；
   玩家侧急救说明 `mod/package/安装说明.txt:187-209`）
2. **两层防护**：`doorstop_config.ini` 开 `ignore_disable_switch = true`
   （只能免疫 `DOORSTOP_DISABLE`，免疫不了 `DOORSTOP_INITIALIZED`——后者无对应开关）；
   启动器先 `set DOORSTOP_DISABLE=` / `set DOORSTOP_INITIALIZED=` 再直连启动。
   （`mod/launcher/启动（无障碍）.bat`、`安装说明.txt:45-56`、`mod/build.ps1:176-184`）
3. **直连启动必须放 `steam_appid.txt`**：否则游戏认为「不是 Steam 启动」，
   调 `SteamAPI_RestartAppIfNecessary` 把自己交给 Steam 重启，进程 20 多秒后消失——
   这正是「补丁看起来没生效」的最大误判来源。（`CHANGELOG.md:132-188`）
4. **A/B 对照实验才算结论**：同一版本分别用「直连 + steam_appid」与「Steam 启动」
   各跑一次，分别看进程存活、心跳、挂载点。（`tools/ab_test/ab_test.ps1:3-17`）
5. **`makezip.ps1` 直接 `CreateFromDirectory` 只是「侥幸合规」**：本机产物 36 条目
   全为 `/`，因为打包机跑的是 pwsh 7；换 PowerShell 5.1 就退化成反斜杠条目。
   结论：流水线不能停在「口头约定」，要直接发手工构造 `/` 条目的模板脚本。
   （`mod/tools/makezip.ps1:31-33`）
6. **`build.ps1` 有个死分支**：启动器缺失时调用未定义的 `Warn`，`$ErrorActionPreference=Stop`
   下以「无法识别命令」中断构建。（`mod/build.ps1:40-41` vs `:181`）
7. **版本号守卫要脚本化**：从 `Plugin.cs` 抽 `BepInPlugin` 版本 → `[Version]::TryParse`
   → 与 csproj `<Version>` 比对，不一致直接 exit 1。
   （`mod/build.ps1:119-146`；流水线有 G7/G8 原则，没有守卫代码）

### 1.8 探针与取证

1. **探针必须约束「不推进剧情」**：不按数字键选选项、不碰输入框（会推进剧情并触发
   自动存档），只按安全快捷键。（`probe/run_probe.ps1:3-20`）
2. **日志离线分析要能独立复算结论**：期望挂载点核对、朗读来源顺序 vs 游戏自己的
   「新消息」事件顺序对账、符号审计、选项公告形态、错误行扫描，并给退出码。
   （`probe/analyze_log.ps1:3-30`）
3. **分析脚本要自带反向校验**：拿旧版本日志当基线跑必须 FAIL，否则它只是在复述日志。
4. **证据文档必须有「反例」一节，且比结论更重要**：本轮出现探针没发出的按键
   （游戏替玩家选了一次选项）、探针按键环节整体失效、日志首行时间戳≠运行时间。
5. **DLL 被加载后是「用户映射区域打开的文件」**，覆盖必失败；部署脚本要等进程退出，
   再用「临时文件 + 同卷改名」落盘。（`tools/deploy/watch_and_deploy.ps1:3-12`）
6. **日志有两个位置**：`BepInEx/LogOutput.log` 可能启动后停止增长，补丁输出实际进了
   Unity 的 `Player.log`（`AppData/LocalLow/<公司>/<游戏>/`），两个都要看。
7. **UI 结构转储是 UI Toolkit 项目的「场景树」替代品**：F12 写
   `BepInEx/<Mod>_ui_dump.txt`（名字/类型/显隐/文字/几何），附「控件→附近标签」关系
   摘要与设备实时诊断节。（`UiDump.cs:11-23`、`:213-230`）
8. **探针模板缺口**：`templates/probe/ProbePlugin.cs.template` 只 `Walk(Transform)`，
   UI Toolkit 项目里一无所获；需要 `VisualElement` 版。

## 2. justlilith_a11y：Framework 平台的第一个成品，与「编译期查不出的初始化崩」

### 2.1 `NameAlias` 大小写重复键 → 导航 100% 死、零日志

本作把平台层整份内嵌进 `src/JustLilithA11y/`（10 个文件与 Framework 0.2.x 改名后逐字相同），

private static readonly Dictionary<string, string> NameAlias =

`Add` 抛 `ArgumentException` → 类型初始化器失败 → `TypeInitializationException` →
`UiNav` 类初始化 **100% 失败**，而且**一行日志都没有**。

## 3. manosaba_a11y：IL2CPP、Naninovel 与「日志全绿、功能全死」

### 3.1 与 Framework 的关系

归一化 namespace 后 9 个 L1 文件中 8 个与 Framework 0.2.4.0 **逐字节相同**，
唯一差异是 `Hotkey.cs` 多了 5 行「`=` / 全角「＝」→ `KeyCode.Equals`」映射。
这 5 行已回灌 Framework（0.2.5.0）——它同时说明：**逐作会先修平台层，
回灌不是可选项**。

### 3.2 Naninovel：不要补返回 `UniTask` 的方法

补 `TextPrinterManager.Print`（返回 `UniTask`）后实机抛
`MethodAccessException: 'Naninovel.Async.IAwaiter.get_IsCompleted'`，
剧情**永久卡住**，但文字还在被朗读——玩家完全不知道游戏已经死了。
→ 补丁前必须看返回类型，只补 `void` / 简单可 blittable 类型（G15）。
替代做法：挂「打印开始/结束」的同步回调或每帧读公开状态（`PlayedScript` / `Playing`）。

配套三条：

- **挂载 ≠ 命中**：`GetPatchedMethods()` 只证明 detour 装了；每个补丁要打命中计数，
  否则「补丁已应用」是一句空话（G14）。
- **反编译的 UI 分支可能整体是死代码**：`UIManager` / `CGPanelManager` /
  `VideoPanelManager` / `NameInputManagerTMP` 运行时零实例；可达性必须以探针为准（G16）。
- **限制条件读游戏自己的数据**（如 `_restrictionAreas`），不要靠字段名猜（G29）。

### 3.3 输入：新 Input System、合成输入与「等待输入」

- 只启新 Input System 的游戏，裸 `Input.GetKey*` 全部失效 →
  `A11yHost.UseGlobalKeys = true`（G21）。
- 合成按键要按住 ≥0.4 秒（低帧率下 1 帧可能读不到）；`keybd_event` 的方向键等
  扩展键必须带 `KEYEVENTF_EXTENDEDKEY (0x0001)`，否则 `GetAsyncKeyState(VK_DOWN) = 0`。
- `ExecuteEvents` / `Button.onClick.Invoke()` 返回成功 ≠ 游戏认账；新 Input System 下
  必须 `InputSystem.QueueStateEvent<MouseState>` + 每帧 Tick 并在之后松开（G22）。
- 「等待玩家输入」的异步操作未完成时，**其他热键一律不响应**，
  否则会把游戏点进 loading 软锁（G23）。

### 3.4 测试三层与 PowerShell 测试坑

1. **插件内 `SelfTest`**：IL2CPP 类型在进程外拿不到，断言必须写在插件里；
   环境变量 `MANOSABA_A11Y_SELFTEST=1` 打开，30 帧后打印 `SELFTEST SUMMARY`。
2. **进程外 `Harness`**：`tests/Suite.ps1` 启游戏 → 标题 → 跳转 → 推进 → 读日志断言，
   退出码 = 失败数；只读日志，不碰进程内存。
3. **人工听觉**：语速、断句、双播只能耳朵判定。

PowerShell 测试坑（全部实测）：

- `MainWindowHandle` 可能拿到 BepInEx 控制台窗口 → 必须 `EnumWindows` 并排除
  `ConsoleWindowClass`；
- `LogOutput.log` 读的时候要 `FileShare.ReadWrite | Delete`，否则游戏还在写就打不开；
- 单元素数组会被 PowerShell 降成标量 → `@()` 包一层；
- `pwsh -File x.ps1 -Only a,b` 的 `a,b` 会作为**一个字符串**到达；
- 测试**不能写 `ConfigEntry.Value`**：会落盘污染玩家配置；用内存开关。

### 3.5 性能：先测量，再分档

- 实测 1.8–14 FPS、单帧 71–570 ms；标题/演出场景调质量有 +37% / +65% / +95%，
  ADV 场景约 8 FPS **无收益** —— 收益依场景而变，不能一概而论。
- 自身每帧开销从 10–13 ms 降到 2.5–5 ms；`Resources.FindObjectsOfTypeAll` **禁止进每帧路径**
  （5–10 ms），扫描用 `ScanGate.Ready` 节流（0.4–2 s）。
- 低性能档 5 档；换档必须**全量 `Restore()` → `Apply()`** 再增量补扫；
  保存/恢复要记账，逐档验证单调。

### 3.6 发行包与证据

- IL2CPP 包 = BepInEx 6 core（5 文件）+ interop（`Assembly-CSharp` / `Il2Cppmscorlib` /
  `CoreModule` / `UnityEngine.UI` / `UIModule` / `TextMeshPro` / `InputLegacyModule` /
  `Physics2D` / `AudioModule`，**逐个列出、禁通配**、必须非 0 字节）+
  patched `Il2CppInterop.Runtime.dll`（按 SHA 配对）+ 插件 + 文档 + 许可证。
- 发行包逐项自检 12 条（流水线 P6），任何一条失败 `exit 1`。
- 证据库教训：258 文件包里混进 **89 MB / 444 个 `.bin`** 的证据目录，
