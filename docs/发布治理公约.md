# 发布治理公约

> 适用：`Nornageste-mh` 名下**全部仓库的发布行为**——无论仓库进不进补丁流水线。
> 协作方式见 [`协作指南-与AI协作的人类.md`](协作指南-与AI协作的人类.md)、
> [`协作指南-独立人类开发者.md`](协作指南-独立人类开发者.md)、
> [`协作指南-AI开发者.md`](协作指南-AI开发者.md)。

## 1. 缘起：实证事故（2026-11-04 发布治理体检）

| 事故 | 后果 |
|---|---|
| 版本号带字母（`0.5.8a`） | BepInEx 判 `version is invalid`，**静默跳过整个插件**；补发 `v0.5.8a(Reset)` 救场 |
| Release 正文写的包名与实际附件不符 | 用户下到错包 / 旧包 |
| Release 正文附件名少 `v` 前缀 | 与安装说明对不上 |
| 旧版本包残留在新 Release | 同上 |
| tag 有、Release 无（或反之） | 版本对账靠猜 |
| 提交信息版本与 tag 脱节 | 复现构建找不到锚点 |
| 包内容自检从未通过却照发（手工打包） | 质量门形同虚设 |

体检口径：37 个 Release / 71 个 Tag，半数 tag 无对应 Release；五套版本风格并存。

## 2. 公约四条

1. **版本号 = `v` + 纯数字四段**（如 `v0.2.7.0`），禁止字母后缀；
   `[BepInPlugin]` 的 `Version`、csproj `<Version>`、CHANGELOG 三处**完全一致**。
   想表达「第五版修订」用 `0.5.8.1`，不用 `0.5.8a`。
2. **tag ↔ Release 对账**：每个 tag 要么有对应 Release，要么在 CHANGELOG 注明
   「未单独发版」及原因；不允许无注释的孤儿 tag。
3. **三件套必有**：`LICENSE` + `NOTICE.md` + `CHANGELOG.md`；
   README 标题与仓库名一致；`CHANGELOG` 每个修改单独一节（现象 → 后果为何严重 → 怎么修）。
4. **发布走统一脚本，禁手工打包**：平台层只能来自 Framework（tools 校验哈希，G33 口径）；
   `release.ps1` + `tools/makezip.ps1` + 流水线 P6 的 12 项自检，**任何一项失败即停**（exit 1，
   不许「警告后继续」）；绝不用 `Compress-Archive`（WinPS5.1 条目反斜杠，Linux unzip 不容忍）。

## 3. 发布前检查（引用流水线 P6）

版本三处一致；运行时按路线齐全（Mono / IL2CPP 分支）；Il2CppInterop SHA 配对；
`nvdaControllerClient.dll` x64 两处齐全；安装说明 + 常见问题在包内；licenses 按路线；
不含 `interop\` / `unity-libs\` / `dl\` / `config\<guid>.cfg`；不含剧本文本 / 截图 / `LogOutput.log`；
无他作模板残留；zip 条目分隔符全 `/`；包层级与安装说明一致。

## 4. 待建工具（建成后本公约升级为强制门）

- **跨仓一键发版 fan-out**：Framework 先发 → 其余仓库同步；当前人肉 fan-out 的历史节奏是
  3 分钟 6 仓、1 分钟 5 仓，发布说明逐字复制改 6 个变量——出错只是概率问题。
- **发布一致性 linter**：拦截 §1 表中六类错误（版本字母、附件名不符、旧包残留、tag 对账、
  提交版本脱节、自检未过）。
- **文档模板同步 bot**：以 `docs/templates/` 为单一事实源，替掉「N 仓逐字手工重放」。
